# Guard v6: retreino de correção com benignos técnicos

> Relatório escrito durante o estudo (06/10/2026), em português. Os caminhos foram trocados pelos deste
> repositório e os comandos de infraestrutura privada saíram; os números são os originais.

Rodada de 06/10/2026. Objeto: o classificador de prompt injection ("guard") deste estudo, e5-large ajustado, foco pt-BR.
Números brutos em `results/v6/v6.json`; as tabelas abaixo saem de `analysis/comparar_versoes.py`.

## Resumo

A v3 dava aviso falso em 100% das páginas técnicas (READMEs de pacotes). A hipótese era falta de texto técnico benigno
no treino. A v6 repete a receita da v3 e só acrescenta 10.000 negativos técnicos (StackOverflow e docstrings). Resultado:

- **A hipótese se confirma.** Em frase técnica benigna, o aviso falso caiu de 38–87% (v3) para 0% (v6), com n = 300
  por fonte. A fração de janelas de README marcadas como injeção caiu de 99,6% para 7,2%.
- **A correção não basta para o hook.** Por página, o aviso falso caiu de 100% para 34,6% (limiar 0,5) e 19,4% (0,999).
  O critério (aviso falso ≤ 2%) continua inalcançável em qualquer limiar. O que sobra são trechos de README que o treino
  não cobre: badges HTML, links de patrocínio, tabelas markdown.
- **A correção custou a detecção em pt-BR.** No Weni (injeção pt-BR nativa) a v6 acerta 63,7%; a v3 acertava 94,7%
  (McNemar p < 1e-6). Nos 242 textos do Weni sem contaminação a queda vai de 93,4% para 60,7%. Os outros testes de
  ataque ficam iguais ou melhores (xTRam1-pt 96,0% → 98,2%), exceto o deepset (94,8% → 88,8%).
- **Leitura:** parte do acerto da v3 no Weni vinha do mesmo atalho que gerava o aviso falso ("texto com cara de
  instrução = ataque"). Quando o modelo aprende que instrução técnica é benigna, os ataques do Weni enquadrados como
  tarefa ("gere um título...", "traduza...") passam a parecer benignos. **Nenhuma das duas versões atende os dois
  critérios.** A v3 segue como a versão para frase; o hook continua desligado.

## 1. Pergunta e desenho

Pergunta: acrescentar texto técnico benigno ao treino resolve o aviso falso em página técnica sem perder detecção?

Desenho controlado. Muda uma coisa só, o conjunto de treino:

| | v3 | v6 |
|---|---|---|
| exemplos de treino | 23.693 | 33.578 |
| positivos (injeção) | 9.436 (39,8%) | 9.338 (27,8%) |
| relação | — | v3 − 115 quase-duplicatas do Weni + 10.000 benignos técnicos |
| benignos técnicos novos | 0 | 4.000 perguntas do StackOverflow (`pacovaldez/stackoverflow-questions`), 4.000 respostas (`koutch/stackoverflow_python`), 2.000 docstrings Python (`Nan-Do/code-search-net-python`) |
| HackAPrompt | fora | fora |

Conferido no arquivo exportado: 23.578 dos 23.693 textos da v3 estão na v6, idênticos. Os 115 que faltam são os que
a trava anti-vazamento tirou (cosseno e5-base > 0,9 com algum texto do Weni). A v3 foi exportada antes de a trava existir.

O que não muda:

- Receita (`kaggle/guard-treino.ipynb`): `intfloat/multilingual-e5-large`, 3 épocas, lr 2e-5, lote 8 × 4, aquecimento de
  6%, fp16, `max_length` 256, prefixo `query: `, validação interna de 8% estratificada. Kaggle 2× T4. Validação interna:
  v3 99,63%, v6 99,70%.
- Instalação: igual à da v3 (`models/prompt_injection-e5large-v6`, temperatura 1, prefixo `query: `). Não houve ajuste
  de temperatura, porque a v3 também não teve.
- Avaliação: mesmos testes, mesmos textos, mesmo código e mesma máquina (VM ARM na nuvem, CPU fp32) da avaliação original da v3.
  Os testes que a v3 não tinha rodado (técnicos, deepset, jackhhao, SPML) foram rodados agora para as duas versões, com os
  mesmos 300 primeiros itens. Página: as mesmas 217 páginas benignas e 60 com injeção (impressão `349cf30a6cebfa99` nas duas).
- Comparação pareada: os dois modelos veem os mesmos itens na mesma ordem. Usamos McNemar exato e intervalo de Wilson 95%.

Auditoria de contaminação do teste por página: nenhum texto de treino é idêntico a um README dos 329 METADATA dos ambientes locais (superconjunto das
217 páginas).
Nenhum trecho de 200 caracteres ou mais aparece nos dois. Só 9 textos compartilham algum 13-grama, e todos são boilerplate
XML/XHTML (DOCTYPE, xmlns XSL).

Ressalvas de leitura:

- Os testes técnicos estão **dentro da distribuição da v6**: mesmas bases do treino, só que 20% separados por hash.
  O teste que importa para o hook é a página (READMEs). Nenhum README entrou no treino.
- A v6 também mudou a proporção de positivos (39,8% → 27,8%), o que empurra a decisão para "benigno". Isso não explica o
  Weni: baixar o limiar quase não recupera o acerto (0,5 → 63,7%; 0,1 → 67,0%; 0,01 → 69,3%). O motivo é que 23% dos

  benignas acima de 0,5 viram 34,6% de páginas com aviso. Para ficar em 2% por página, o erro por janela teria de ser
  de cerca de 0,2%.

## 3. Onde cada versão erra

**Weni perdido pela v6** (a v6 erra 94 textos que a v3 acerta; o contrário acontece 1 vez): são os ataques curtos
(705 caracteres em média, contra 1.101 dos demais), apresentados como tarefa legítima: "gere um título de filme sobre a
frase...", "traduza...", "você é um mecanismo de busca...". O alvo "I have been PWNED" vem fatiado ou ofuscado. Sem o
atalho, sobra pouca pista de ataque.

**Páginas que a v6 ainda marca** (75 das 217 acima de 0,5; mediana de 2 janelas disparadas por página): o trecho
culpado é boilerplate de README que não existe em pergunta do StackOverflow nem em docstring. Exemplos: badges em
HTML (`<img src="https://img.shields.io/...">`), links de patrocínio e doação, tabelas markdown e listas de links.

**Contaminação na v3**: 58 dos 300 textos do Weni têm um vizinho muito próximo (cosseno > 0,9) entre os 115 exemplos de
treino que só a v3 viu. Esses 115 são 98 positivos e 17 negativos, quase todos traduções: 48 do jackhhao, 18 do SPML,
10 do deepset e 10 do Dolly, além de 12 do rikka, 9 do ShieldLM e 8 do jackhhao em inglês. A v3 acerta 100% dos 58
textos afetados e 93,4% dos outros 242. Logo, o 94,7% publicado da v3 tem cerca de 1,3 p.p. de vazamento. Mesmo nos 242
limpos, a queda da v6 é grande e significativa: 80 contra 1, McNemar p < 1e-6.

## 4. Problemas encontrados no caminho (todos corrigidos ou contornados)

1. **A config da v6 mudava as bases antigas.** O `texto_de` novo fazia strip e limpeza de HTML em todas as fontes, e
   16.011 de 16.011 textos do SPML têm espaço nas pontas. Isso mudava o sorteio por hash, trocava os testes da v3 e
   exigia cerca de 500 traduções novas (cerca de 2,5 h de CPU). Agora só as fontes de `limpar_html` passam pela limpeza;
   as demais entram cruas, como antes. Com isso, 0 traduções ficaram pendentes.
2. **`--avaliar` quebrava com `KeyError: 'choice'`.** Desde que o classificador binário passou a responder `noul`,
   a resposta não tem mais o campo `choice`. A classe agora é a de maior probabilidade.
3. **Memória da máquina local.** A primeira exportação morreu com exit 139, e a avaliação local do e5-large deu
   `MemoryError`. A causa foi o commit do Windows esgotado (navegador com cerca de 19 GB e WSL com 8 GB). Toda a
   inferência foi para a VM ARM.
4. **Token OAuth do Kaggle vencido no meio da rodada.** O erro aparecia como "Permission kernels.get denied"; foi
   renovado pelo próprio SDK, com o refresh token. A versão 6 do kernel terminou em ERROR sem log; a versão 7,
   idêntica, completou (3 h 32 min).
5. **`guard_paginas.py` pedia 256 janelas por chamada**, o que estourava os 600 s do cliente no ARM dividido com outra
   avaliação. Agora pede 32 por vez.
6. **A seleção de páginas ao vivo mudou entre a v3 e a v6.** Pacotes novos num ambiente local trocaram 21 das
   217 páginas e alteraram 2. A v6 foi medida nas páginas congeladas (hoje remontáveis por
   `bench/paginas/construir.py`, mesma impressão da medição da v3). Sem essa trava, a comparação de página seria inválida.

## 5. Conclusões

1. A causa do aviso falso da v3 está identificada: a v3 confunde texto técnico com injeção. Acrescentar benignos técnicos
   remove esse aviso falso em frase e reduz o erro por janela de README em cerca de 14 vezes (99,6% → 7,2%).
2. Os benignos técnicos não bastam para ligar o hook. O aviso falso por página fica entre 19% e 35%, e o critério de 2% é
   inalcançável. O próximo negativo difícil é o boilerplate de README (badges, links, tabelas), tirado de uma fonte que
   **não** seja o METADATA dos pacotes do benchmark.
3. A detecção do Weni dependia, em boa parte, do mesmo atalho. Corrigir o aviso falso sem trazer junto ataques em pt-BR
   apresentados como tarefa troca um problema por outro. A v6 reprova no critério de frase (Weni ≥ 95%), e a v3 reprova
   na página.
4. A medição tem limites que importam para o artigo. O 94,7% da v3 tinha vazamento (93,4% limpo). A seleção de páginas
   ao vivo não era reprodutível. As probabilidades gravadas com 4 casas impedem a análise fina de limiar perto de 0 e de 1.

Próximos passos sugeridos (fora do escopo desta rodada):

- Controle "v3 limpa" (v3 − 115, sem os benignos técnicos), para separar o efeito da trava do efeito dos negativos técnicos.
- v7 = v6 + negativos de README (de outra fonte) + positivos pt-BR enquadrados como tarefa (não Weni; trava de vazamento ativa).
- Gravar logits crus na avaliação, em vez de probabilidades com 4 casas.

## 6. Reprodução

```
# exportar (só dado público; traduções do cache)
python pipeline/treinar.py exportar --rodada v6 --saida work/v6
python pipeline/treinar.py exportar --rodada v3 --saida work/v3
python bench/paginas/construir.py
python analysis/checar_vazamento_paginas.py work/v6/treino.jsonl --base-antiga work/v3/treino.jsonl
# treinar (Kaggle, GPU)
python kaggle/gerar_notebook.py
python kaggle/publicar.py dados --dataset ptguard-treino-v6 --arquivo work/v6/treino.jsonl
python kaggle/publicar.py treinar --dataset ptguard-treino-v6 --kernel ptguard-finetune
python kaggle/publicar.py baixar --kernel ptguard-finetune --saida work/v6/saida
# avaliar frases (--max-teste 300 nos extras, igual para v3 e v6)
python pipeline/treinar.py avaliar models/prompt_injection-e5large-v6 --testes weni,xtram1-pt,fumaca
python pipeline/treinar.py avaliar models/prompt_injection-e5large-v6 --max-teste 300 \
  --testes deepset,deepset-pt,jackhhao,jackhhao-pt,spml,spml-pt,so_perguntas,so_respostas,docstrings,dolly
python pipeline/treinar.py avaliar models/prompt_injection-e5large-v6 --testes xtram1,massive_pt,dolly-pt
# avaliar página (as mesmas 217 + 60 páginas)
python bench/paginas/avaliar.py models/prompt_injection-e5large-v6 --janela 640 --sobra 160
# tabelas e JSON: a partir dos dados por item publicados, refaz results/v6/v6.json e v6-tabelas.md
PTGUARD_CACHE=results/v6/dados python analysis/comparar_versoes.py --base v3 --nova v6 ...   (comando completo em v6.json > extra.avaliacao)
```

Dados por item (públicos) em `results/v6/dados/`: P(injeção) e gabarito por teste (`probs/v3`, `probs/v6`),
pior janela por página e todas as janelas (`paginas-640-160-v3.json`, `paginas-640-160-v6.json`) e o vizinho mais
próximo de cada texto do Weni entre os exemplos que só a v3 viu (`weni_vizinhos.json`). Resultados brutos da
avaliação em `results/guard/` (mapa em `results/README.md`).
